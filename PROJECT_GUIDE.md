## 4. Как работает один проход `run.py`

`main()` вызывается каждые 2 минуты внутри одного долгого job (см. §9). Порядок:

1. **Переобучение раз в сутки** (`learn`, [run.py](projects/betbot/run.py:193)) — качает свежие результаты
   football-data и пересчитывает вес «модель против рынка» на последних двух годах walk-forward.
2. **Расписание** — ESPN `scoreboard` по ~72 лигам × 3 дня (−1/0/+1), фильтр переносов/отмен,
   кубковые матчи только между профессиональными командами (`CUP_SOURCES`).
3. **Русские названия** — только для матчей ±30 часов, с бюджетом 40 с на Wikidata.
4. **Прочие виды** — хоккей/баскетбол/теннис/киберспорт через ESPN и PandaScore (`sports.fetch`).
5. **Утренний блок** (после 08:00, один раз в день): обложка дня → статистика за вчера/7/30/всё →
   расписание на день → 3 закреплённых «прогноза дня».
6. **Тематический пост слота** (`content.run`): 10:00 экспресс, 13:00 ликбез/опрос, 16:00 матч дня,
   19:00 вечерние матчи, 20:00 «экспресс на яйцах», 22:00 цифры, 23:00 итоги дня.
7. **Прогнозы на матчи**: публикуются за 60–80 минут до начала (`lead = 60 + LOOP_MINUTES`):
   картинка + подпись, полный разбор — ответом в ветку.
8. **Итоги**: как только матч завершён — карточка со счётом, ✅/❌ по каждому прогнозу, статистика за день;
   запись в `data/results.csv`.
9. **Live**: «МАТЧ НАЧАЛСЯ», голы/карты — ответами в ветку прогноза; ⚡ LIVE-прогноз в моменте игры.
10. **Push-уведомления** подписчикам сайта (Firebase), еженедельная пятничная рассылка.
11. **Ролики** в 12:00: «заход дня» + «экспресс зашёл» → Telegram, ВК, YouTube, Дзен-личка.
12. **Сайт**: страницы новостей/прогнозов/команд/watch, JSON для мини-аппа, sitemap, IndexNow.
13. **Кросспостинг**: ВК (`vk.crosspost`), Дзен-канал (`dzen.crosspost`), новости — сразу картинкой в Дзен.
14. **Мелочи**: новость раз в ~30 минут (`news.run`), таблица дня (`tables.run`), ответы в личке бота
    (`/dzen`, `/stats`, `/matches`), разовые переотправки по `data/repost.json`.

Всё состояние живёт в `data/` и коммитится в git после каждого прохода — это и есть «база данных» бота.

## 6. Модель и логика прогноза

**Матрица счёта.** Из вероятностей 1X2 (и тотала 2.5) через оптимизацию Нелдера–Мида подбираются
ожидаемые голы `λ_home`, `λ_away` так, чтобы модель повторяла рынок
([markets.py](projects/betbot/betbot/markets.py:108)). Дальше строится матрица Пуассона 11×11 с поправкой
Диксона–Коулза (`ρ = −0.08`) и из неё считаются **44 рынка**: исход, двойной шанс, обе забьют,
тоталы 1.5/2.5/3.5/4.5, индивидуальные тоталы, форы ±1.5/±2.5, комбо, 7 рынков первого тайма.

**Своя модель.** Пуассон с силами атаки/обороны по каждой команде, полураспадом 240 дней и
псевдонаблюдениями для новичков ([model.py](projects/betbot/betbot/model.py:13)). Обучается на 3 годах
истории, прогоняется «как в реальности» по неделям (walk-forward, [engine.py](projects/betbot/betbot/engine.py:35)),
и бот сам решает, какой вес ей дать против рынка: перебирает 21 значение `w` и минимизирует log-loss
([engine.py](projects/betbot/betbot/engine.py:78)).

**Сейчас вес = 0** (`{"1X2": 0.0, "OU25": 0.0}`) — рынок оказался точнее, модель в прогнозе не участвует.

**Выбор ставки** ([markets.py](projects/betbot/betbot/markets.py:255)):
- основной — рынок с настоящим кэфом ≥1.5 и вероятностью ≥45%, максимальный `p × кэф`;
- смелый — только настоящий кэф 2.0–3.6, шанс ≥40%, не спорит с основным;
- при явном фаворите (≥60%) не ставим против него;
- калибровка: бот считает, во сколько раз каждый тип ставки заходит чаще/реже обещанного, и
  «подводящие» рынки временно отключает (клип 0.75–1.25, отключение при провале >10 п.п. за 30 дней).

**Ставка** — четверть-Келли, 1–3% банка ([pro.py](projects/betbot/betbot/pro.py:22)). Виртуальный банк
стартует с 10 000 ₽ и пересчитывается по процентам от текущего.

**Value-ставки** — отдельная ветка: где лучший кэф выше «честной» цены на 5–30% (кэф 1.5–4.0),
пост в 11:00, журнал `data/value_bets.csv`, расчёт итога раз в 3 часа. Выборка пока мизерная (2 ставки).

**Что честно признаёт сам README:** букмекеров стабильно обыгрывают немногие; основной прогноз — самый
вероятный исход, а не гарантированная прибыль. Текущий ROI −4,3% это подтверждает.

## 7. Публикации

### Telegram
Единственная точка выхода — `telegram.py`. Текст 4000 символов, подпись 1024, после каждого поста пауза 3 с
(~20 сообщений/мин). Длинный текст → картинка + продолжение ответом. Кнопки «Смотреть онлайн» ведут в
мини-приложение (`t.me/...?startapp=m<id>`) или на сайт. Хештеги добавляются автоматически по первой строке.
Ретраи только на 429.

### ВК
`vk.crosspost`: до 5 новых постов за проход, через 9+ минут после публикации (чтобы страница уже была на сайте
и ВК показал карточку ссылки). Текст вычищается от упоминаний букмекеров, фото грузится на стену,
ссылка сокращается через `vk.cc`. Нужен `VK_USER_TOKEN` с правами `wall`, `photos`, `offline` — ключом
сообщества стена недоступна.

### Дзен (два разных механизма!)
1. **Канал-фильтр** `@aistavvit_dzen`: бот копирует туда только разборы, «матч начался», итоги и новости.
   Сам Дзен забирает посты оттуда через `@zen_sync_bot`. Новости туда идут сразу картинкой (видео Дзен не берёт).
2. **Личка владельцу** — только для роликов: раз в день бот шлёт видео + готовые заголовок/описание/теги,
   чтобы их загрузили в Дзен-Студию руками. Работает **только после команды `/dzen`** боту (запоминается
   первый, кто её отправил, — `state["dzen_chat"]`).

### YouTube Shorts
`shorts.py` собирает ролик 1080×1920 из трёх сцен (прогноз → итог → призыв), 14 секунд, без звука
(иначе Telegram покажет как GIF). Загрузка — через OAuth-refresh и resumable upload, категория «Спорт» (17),
`public`, язык `ru`. Нужны три секрета: `YT_CLIENT_ID`, `YT_CLIENT_SECRET`, `YT_REFRESH_TOKEN`.
Лимит бесплатного API — 10 000 единиц в день, загрузка ~1600 → 6 роликов/день (бот делает 1–2).

### Картинки
Всё рисуется на Pillow: тёмный градиент со свечением цветов команд, случайный декор из 6 стилей,
виньетка, зерно, золотые уголки. Карточки: обложка дня, статистика, расписание, превью матча (логотипы,
форма, шансы, плашка с кэфом), итог матча, live, экспресс, value, серия, топ-3 дня, новость, промахи, таблица.

## 9. Инфраструктура: почему бесплатно

`daily.yml` запускает **один job на 5,5 часа** (timeout 350 минут), внутри — bash-цикл: каждые 2 минуты
`timeout 900 python run.py`, затем коммит изменившегося `data/` и `docs/`, `git pull --rebase`, `git push`
(до 3 попыток). В конце job сам запускает следующий (`gh workflow run daily.yml`) — цепочка не зависит
от расписания. Расписание `*/30 * * * *` — страховка, если цепочка оборвалась. `concurrency: betbot`
гарантирует одну копию.

Публикация сайта — отдельный workflow `pages.yml` (только когда меняется `docs/`), с версионированием
`site.css`/`fb.js`/`espn.js` по хешу (сброс кэша в браузерах и мини-аппе).

**Секреты репозитория** (значения мне недоступны): `TELEGRAM_TOKEN`, `TELEGRAM_CHAT_ID`, `VK_TOKEN`,
`VK_USER_TOKEN`, `PANDASCORE_TOKEN`, `ODDSPAPI_KEY`, `GROQ_KEY`, `OPENROUTER_KEY`, `FIREBASE_SA`,
`YT_CLIENT_ID`, `YT_CLIENT_SECRET`, `YT_REFRESH_TOKEN`.

**Квоты, за которыми надо следить:** OddsPapi 230/250 запросов в месяц (израсходовано 164 за ноябрь),
YouTube 10 000 единиц/день, Telegram ~20 сообщений/мин, ESPN без ключа (может троттлить), Wikidata
бюджет 40 с на запуск.

## 11. Риски и слабые места

**Смысловые (влияют на результат):**
1. **Вес модели = 0.** Ежедневный walk-forward считается «в стол», прогнозы полностью рыночные.
2. **Смешение вероятностей и λ.** Вес обучается на смеси вероятностей, а применяется к лямбдам — при `w` в
   середине диапазона это не одно и то же. Вес `OU25` обучается, но не используется.
3. **ROI ≈ −4,3%.** На 884 прогнозах это ровно «маржа букмекера». Основной канал заработка — реферальная
   ссылка BetBoom, а не точность.
4. **Хоккей — самое слабое место:** 44,4% заходов основного прогноза (против 57–61% у остальных).
5. **Value-ставки** выбираются по лучшему кэфу и игнорируют калибровку — могут попасть на рынок, который
   бот уже отключил как «подводящий».

**Технические (могут сломать бота):**
6. `espn.scoreboard` делает ~216 запросов за проход без кэша; `_event` не защищён от `KeyError` — упадёт весь запуск.
7. `implied_lambdas` без границ + матрица Диксона–Коулза без клиппинга: при больших λ возможны
   отрицательные «вероятности».
8. OddsPapi сжигает лимит на неудачные запросы (счётчик увеличивается до ответа) — к концу месяца
   теннис/киберспорт могут остаться без линии.
9. `names.norm` вырезает кириллицу: сравнение двух русских названий даёт ложное совпадение 1.0 (сейчас не
   стреляет, но ловушка).
10. Кибеспорт BO2: вероятность победы в матче используется как вероятность карты — перекос в 2:0/1:1/0:2.
11. `watch.build(now)` вызывается без `preds` — ссылки «полный разбор» на этих страницах не появляются.
12. Папки `news/` и `predictions/` не чистятся (645+296 файлов уже), при этом выпадают из sitemap.
13. IndexNow уведомляет только о **новых** страницах, обновления не переотправляются.
14. Домен/владелец/ветка захардкожены в 6+ файлах — переезд на свой домен = правки в нескольких местах.
15. `shorts.run` ставит `shorts_day` **до** рендера: любая ошибка ffmpeg — ролика в этот день не будет.
16. Токен Telegram подставляется в URL — при трассировке requests может попасть в лог Actions.

**Правовые/платформенные:**
17. Новости пересказываются с фото источника (флаг `SOURCE_PHOTOS = True`) — риск претензий правообладателя.
18. Страницы «смотреть онлайн бесплатно» фактически ведут на 3D-трекер, а не на трансляцию.
19. Реклама BetBoom (18+, «фрибет до 10 000 ₽») на главной и кнопках.

## 12. Что делать дальше

### Завтра: YouTube (15 минут, бесплатно, карта не нужна)
1. `console.cloud.google.com` → новый проект.
2. «APIs & Services» → Library → **YouTube Data API v3** → Enable.
3. «OAuth consent screen» → External → название, почта → scope `youtube.upload` → **Publish app**
   (в тестовом режиме доступ слетает каждые 7 дней).
4. «Credentials» → OAuth client ID → **Web application** → redirect URI
   `https://developers.google.com/oauthplayground` → сохранить **Client ID** и **Client secret**.
5. `developers.google.com/oauthplayground` → ⚙ → «Use your own OAuth credentials» → вставить ID и secret →
   scope `https://www.googleapis.com/auth/youtube.upload` → Authorize → войти в аккаунт канала →
   «Exchange authorization code for tokens» → скопировать **Refresh token**.
6. GitHub → репозиторий betbot → Settings → Secrets and variables → Actions → добавить три секрета:
   `YT_CLIENT_ID`, `YT_CLIENT_SECRET`, `YT_REFRESH_TOKEN`.
7. Секреты подхватываются при **следующем** job (цепочка перезапускается каждые 5,5 часа) — либо сразу:
   Actions → BetBot → Run workflow. Проверка: через сутки в 12:00 ролик должен появиться на YouTube,
   а `shorts_err` в `data/state.json` — исчезнуть.

## 13. Локальный запуск

```powershell
cd projects\betbot
pip install -r requirements.txt
python run.py          # без TELEGRAM_TOKEN посты пишутся в data/preview/ (текст + png)
python backtest.py     # проверка модели на прошлых сезонах
python -m http.server 8765 --directory docs   # посмотреть сайт локально
```

Важно: `run.py` без секретов — безопасный «сухой прогон» для Telegram, но `dzen.post_news` и `vk` идут в API
напрямую, поэтому для локальных экспериментов лучше завести отдельный тестовый канал/сообщество.
